MODULE 01 · THE BIG PICTURE

First, what do we mean by Artificial Intelligence?

Artificial Intelligence (AI) is the broad field of creating computer systems that perform tasks that normally require human-like capabilities — such as recognising patterns, understanding language, making recommendations, planning actions or supporting decisions.

✧

AI is the umbrella

AI is the overall goal: build a system that performs an intelligent task. It may use rules, search, planning, machine learning, or a combination of these techniques.

BROAD FIELD
⌘

Not every AI learns

A chess program can search possible moves and choose a strong one. A rule-based alarm can trigger when a temperature exceeds a limit. Neither needs to learn from examples.

RULES · SEARCH · PLANNING
◉

Not a human mind

An AI system can produce impressive results without having human feelings, intentions or understanding. Its behaviour comes from its design, data and operating process.

CAPABILITY ≠ CONSCIOUSNESS

The AI family: how the terms fit together

Machine Learning is one approach within AI. Deep Learning is a specialised area of Machine Learning that uses multi-layer neural networks. Generative AI is commonly built using deep-learning models that generate new content. These terms describe related layers of a field, not four competing products.

MODULE 02 · THE LEARNING PROCESS

How does a machine learn from data?

A machine-learning model is not manually given every possible answer. Instead, we provide relevant examples and a learning algorithm adjusts the model's internal parameters so its outputs become more useful for the task.

A / DATA

Collect relevant examples

Start with examples connected to the problem. If the goal is to estimate house prices, collect historical property sales. Each row should describe a property and its known sale outcome.

Why it matters: unrelated, outdated or unrepresentative examples can teach the model misleading patterns.

B / PREPARATION

Make the data usable

Real-world data often contains missing values, duplicates, inconsistent units, spelling differences and incorrect entries. Preparation makes records more consistent before training.

Example: standardise area to square feet, handle missing bedroom counts and remove duplicate sale records.

C / TRAINING

Let the algorithm adjust

The learning algorithm compares model outputs with known answers when labels are available. It calculates an error or loss and updates internal parameters to reduce that error.

Important: the model learns statistical relationships; it does not understand the real-world cause of every relationship.

D / EVALUATION

Test beyond the practice set

Evaluate the model using examples it did not train on. This checks whether it learned patterns that generalise rather than simply performing well on familiar records.

Why it matters: a model that only works on its training data is not ready for real use.

MODULE 03 · THREE LEARNING APPROACHES

Three ways a model can learn.

The learning approach depends on what information is available and what the system is expected to achieve. The most important distinction is whether examples come with known answers, whether the system must discover structure, or whether it learns through feedback from actions.

KNOWN ANSWERS · LABELLED DATA

Supervised learning — learning with an answer key

Each training example contains input information and a known correct answer, called a label. The model makes a prediction, compares it with the answer key and adjusts to reduce the difference. Once trained, it can predict labels or values for new examples.

Example: give a model thousands of emails marked “spam” or “not spam”. It learns patterns associated with each category and can classify a new email.

Unsupervised learning — discovering hidden structure

The examples do not come with a correct target answer. The algorithm explores similarities, differences or structure in the data. It may discover clusters of similar customers or represent complex data with fewer dimensions.

Example: a retailer groups shoppers using purchase frequency, average spend and product preferences. A human analyst then interprets and names the groups.

ACTIONS · FEEDBACK · REWARDS

Reinforcement learning — learning through consequences

An agent interacts with an environment, takes an action and receives a reward or penalty. Over many interactions, it learns a policy — a strategy for choosing actions that aims to achieve a goal and maximise long-term reward.

Example: a delivery robot learns a route through a simulated building. Reaching the destination earns a reward; hitting an obstacle receives a penalty. Real deployments require strict safety boundaries.

Clustering and dimensionality reduction

Clustering

Groups records that are similar according to selected features. A retailer might discover frequent high-spend shoppers, occasional shoppers and discount-focused shoppers. The algorithm creates groups; people interpret what those groups mean.

Dimensionality reduction

Represents data using fewer variables or dimensions while preserving important structure as much as possible. For example, hundreds of customer behaviour measures may be compressed into two dimensions for visual exploration. It simplifies analysis; it does not automatically improve decisions.

MODULE 06 · GENERALISATION

Overfitting: when a model memorises instead of learning.

A model is useful when it performs well on new examples, not just the examples it has already seen. Overfitting happens when a model learns noise, accidental details or overly specific patterns in its training data.

GOOD GENERALISATION

Learns the overall pattern

A reasonably simple relationship captures the signal and works on examples it has not seen.

OVERFITTING

Fits the training details too closely

The model follows noise in the training set and may struggle when new data differs slightly.

▤

Exam analogy: memorising the exact answers to a practice test may produce a perfect practice score. If the exam changes the questions, memorisation fails. Understanding the concepts is what helps you handle new questions.

How do we reduce overfitting?

01 · Separate the data

Use training data to learn and separate validation/test data to check performance on unseen examples.

02 · Control complexity

Use a model that is appropriate for the amount and complexity of the data; apply regularisation where suitable.

03 · Improve coverage

Collect representative, reliable examples so the model sees the range of situations it must handle.

✦

Key idea — generalisation: a good model learns relationships that remain useful beyond its training examples. Training performance alone is not enough.

MODULE 07 · MEASURING QUALITY

How do we know whether a model is good?

Evaluation measures how well a model performs on data that was not used to train it. The right metric depends on the task and on the cost of different mistakes.

%

Accuracy

Of all predictions, what proportion were correct? Useful in many settings, but can be misleading when one class is much more common than another.

◎

Precision

Of all cases the model predicted as positive, how many were truly positive? High precision means fewer false alarms among flagged cases.

↗

Recall

Of all actual positive cases, how many did the model successfully find? High recall means fewer missed positive cases.

↔

MAE / RMSE

For numerical predictions, how far are predictions from actual values? RMSE penalises larger errors more strongly than MAE.

For fraud detection, missing fraud can be costly, so recall matters. Too many false alarms also create operational cost, so precision matters. The right balance depends on the business risk.

MODULE 10 · RESPONSIBLE USE

Use AI thoughtfully: strengths and limits.

AI can process large amounts of information and reveal useful patterns, but its output is only as dependable as the data, design, evaluation and operating controls behind it.

WHERE AI HELPS

Strengths

  • Finds patterns across large datasets.
  • Automates repetitive, well-defined work.
  • Can help teams make faster, more consistent assessments.
  • Can surface signals that may be difficult to notice manually.
WHAT TO WATCH

Risks and limitations

  • Predictions can be wrong or uncertain.
  • Biased or incomplete data can create unfair outcomes.
  • Generative AI can produce convincing but false information.
  • Sensitive information may be mishandled if policy is ignored.

BONUS DEEP DIVE · THINK LIKE AN ML PRACTITIONER

From a business problem to a reliable ML solution.

A machine-learning project does not begin by selecting an algorithm. It begins by understanding the decision that needs support, the data available, and the consequences of being wrong. This is the difference between simply training a model and building a useful system.

01 · DEFINE

Translate the business need

“We want AI” is not a problem statement. A useful statement identifies who needs help, what decision is difficult, when the output is needed and what improvement would count as success.

Example: “Identify card transactions that should be reviewed within two seconds, while keeping the daily false-alert workload manageable.” This gives the team an outcome, a latency requirement and an operational constraint.

02 · CHECK DATA

Ask whether the evidence is trustworthy

Check completeness, correctness, representativeness, freshness, permissions and label quality. Historical data can reflect old business rules or human bias. A large dataset is not automatically a good dataset.

Example: If fraud cases were historically under-reported, the label “not fraud” may include transactions that were never investigated.

03 · BUILD & TEST

Establish a baseline before complexity

Start with a simple rule or baseline model. Split data appropriately, prevent leakage, compare candidate models and evaluate on examples that represent future use. A complex model should earn its place by delivering measurable improvement.

Example: Compare a simple threshold-based fraud rule with a trained classifier. Measure recall, precision, review volume and response time.

04 · OPERATE

Monitor after deployment

Real-world data changes. Customer behaviour, fraud tactics, equipment and business processes evolve. Monitor prediction quality, input drift, latency, failures and fairness. Retraining should be controlled and validated, not automatic without checks.

Example: A fraud model may become less effective after criminals change their tactics, even if its original test score was excellent.

01 A bank model predicts whether a transaction is fraudulent or legitimate. Which task is this?
Correct: Classification. The output is a category such as fraudulent or legitimate.
02 A retailer groups customers without predefined segment labels. Which approach is most suitable?
Correct: Unsupervised learning. The system explores similarities and discovers groups without known target labels.
03 What is the difference between training and inference?
Correct: Training learns patterns by adjusting parameters. Inference applies the trained model to new input to produce an output.
04 In a house-price model, which option is a label?
Correct: Actual sale price. Area, location and bedrooms are features; the known sale price is the target label.
05 Why can a fraud model with 99% accuracy still be unsuitable?
Correct: Fraud is often a minority class. A model can achieve high accuracy while catching no fraud, so precision and recall are important too.
